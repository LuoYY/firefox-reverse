## jsvmp_trace 排错（frx-director 08-19，用户实测）

- **现象**：`jsvmp_trace(start)` 后重载页面，`jsvmp_query` 始终 count=0，trace 文件不生成。
- **关键诊断**：
  - `jsvmp_status` 显示 `contentPid=17910` 但 `readingContentProcess=false`。
  - `ls /tmp/firefox-reverse-jsvmp*`：ctl 文件存在（17910），但**无 .ndjson trace 文件**。
  - 对照实验：filter=chunk-libs（普通 JS）同样 0 记录 → 排除 filter 不匹配，确认是 **C++ patch 未生效或 sandbox 拦截**。
  - profile `env_20260818_103100_sgcc-nx_565f8187`；当前命令行启动 PID 17894（marionette 2829），旧进程 2830 已退。
  - user.js 无 `MOZ_DISABLE_CONTENT_SANDBOX=1`、无 JIT 关闭配置（ion/baselinejit/warp/blinterp 均未关）。
  - trace 目录 `traces/jsvmp/` 为空 → C++ patch 从未写盘。
- **根因结论**：`jsvmp_trace` 是 **Phase-1 C++ patch**（`additions/js/src/vm/JsvmpTraceCore.cpp`），需编译进 Firefox Reverse 二进制。当前运行的 Firefox Reverse（Aug 14 12:36 编译）**可能未包含 jsvmp trace patch**，或 content sandbox 拦截 `/tmp` 写盘。
- **核心教训**：jsvmp_trace 是「编译期能力」而非运行期开关——MCP 返回 ok 只代表控制文件写入成功，不代表 C++ patch 在跑。验证法：start 后重载普通非混淆页面，仍无 trace = patch 未编进。
- **当前可用替代方案（攻关三）**：`page_eval` + `hook_inject` 文本层插桩（M50 v13 已验证可行）；jsvmp_trace 待 Firefox Reverse 重新编译或换已编译版本。
